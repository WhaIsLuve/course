# DS-12: структурированное логирование Directory Service

Этот ExecPlan описывает подключение Serilog, локального Seq и бизнес-событий
Directory Service. План выполнен в рабочем дереве и сохранён для последующей
проверки.

## Purpose / Big Picture

Сервис должен выдавать структурированные события в Console и Seq. По одному
HTTP-событию можно определить метод, путь, статус, длительность и request id;
бизнес-события содержат идентификаторы локаций и подразделений. Ожидаемые 4xx
остаются предупреждениями, технические сбои логируются с exception details, а
клиент получает безопасный Envelope.

## Surprises & Discoveries

- Локальный Docker daemon не имел образ Seq, поэтому выполнена проверка
  `docker compose config`, а фактический pull Seq оставлен команде запуска.
- В проекте включены анализаторы с TreatWarningsAsErrors; request level
  callback пришлось оформить без вложенного ternary.

## Decision Log

- Core использует `ILogger<T>`, а не Serilog напрямую, чтобы provider оставался
  инфраструктурной деталью Web. 2026-08-18.
- Бизнес-события пишутся после успешного сохранения, чтобы лог не сообщал об
  операции, которая откатилась или вернула Result failure. 2026-08-18.
- Локальный Seq использует UI `8080:80` и ingestion `5341:5341`; URL sink-а
  задаётся конфигурацией и может быть переопределён переменной окружения.
  2026-08-18.

## Context and Orientation

Web-приложение находится в `backend/DirectoryService/src/DirectoryService.Web`.
Core-сервисы локаций и подразделений находятся в одноимённых папках Core.
Docker-файл расположен в `backend/DirectoryService/docker`. Центральные версии
NuGet находятся в `backend/Directory.Packages.props`.

## Plan of Work

Конфигурация Serilog в `appsettings.json` задаёт minimum level, namespace
overrides, enrichers, Console и Seq. Program регистрирует provider из
конфигурации, добавляет `UseSerilogRequestLogging` и request id в LogContext.
EF Core и Npgsql используют общий `ILoggerFactory` через DI.

Core получает `Microsoft.Extensions.Logging.Abstractions` и source-generated
`LoggerMessage` templates. События создания/изменения локаций и подразделений,
а также attach/detach связей включают отдельные поля идентификаторов.

ExceptionMiddleware оставляет ожидаемые доменные исключения в Result/Envelope,
логирует технические ошибки на Error и заменяет неизвестное exception message в
ответе на безопасное `server.internal`.

## Validation and Acceptance

Команда `dotnet test backend/DirectoryService/DirectoryService.slnx` должна
завершаться с 139 успешными тестами. Web-проект должен собираться без ошибок и
предупреждений. `docker compose config` из каталога `backend/DirectoryService/docker`
должен показывать postgres и seq. При локальном запуске `/health` должен вернуть
200, а Console — одну request-log запись с методом, путём, статусом и elapsed.

## Idempotence and Recovery

Переименование папки и обновление solution повторяемы только если целевая папка
`docker` ещё не существует. `docker compose up -d` безопасно повторять; данные
Seq и PostgreSQL сохраняются в bind volumes. Для отката переименования достаточно
остановить Compose и вернуть путь `docker` к `database` вместе со ссылкой в
solution.

## Interfaces and Dependencies

Добавлены `Microsoft.Extensions.Logging.Abstractions` 10.0.7 в Core и
существующие Serilog packages в Web. Публичные HTTP-контракты Result/Envelope не
изменялись. Seq запускается образом `datalust/seq:latest` с `ACCEPT_EULA=Y`.
